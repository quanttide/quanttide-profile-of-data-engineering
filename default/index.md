# 量潮数据项目（qtdata-project）

> 本档案是「案例式项目」的复盘载体：把一个真实的数据项目做完后，复盘业务经验与问题，沉淀成可开源的数据工程资产。随迭代更新、反映当前理解，不追求一次写全。

## 定位：真实项目 → 数据工程开源

`qtdata-project` 不是要设计一个「产品」，而是承接**真实数据项目**，在做项目的同时，把过程中的经验与成果**复盘、抽象、开源**——最终沉淀为可复用的数据工程方法、工具与案例。

核心逻辑（对应项目复盘流程）：复盘业务经验和问题 → 畅想理想形态 → 形成工作手册、基础教程、README 文档。

## 核心目标：用案例式项目反哺开源

1. **做一个真实的项目**：数据工程必须有第一个真实用户和真实数据，才能找到真正的结构（「整个系统我是第一个用户，只有我最清楚它的结构」）。
2. **复盘成开源资产**：把项目里的字段口径、数据结构、处理流程、质量标准，抽象成别人能直接复用的开源物。
3. **形成案例**：用真实案例优化方法论，吸引企业客户，也降低后续项目的启动成本。

## 阶段方法：五阶段项目制 + 复盘闭环

项目本身按五阶段推进，复盘贯穿始终：

| 阶段 | 项目交付 | 复盘沉淀 |
|------|---------|---------|
| 调研 | 数据需求文档、报价单 | 需求模板 |
| 谈判 | 数据规格书、契约、蓝图 | 契约/蓝图规范 |
| 实施 | 进度汇报 | 流程经验 |
| 验收 | 交付清单、质量报告 | 质量口径 |
| 复盘 | 复盘报告 | 工作手册、教程、README |

## 数据结构：真实项目沉淀的字段与口径

记录真实项目中确定下来的数据结构（从具体项目抽象而来）：

- **数字化链路**：飞书（原始）→ GitHub 私有仓库（Markdown/JSON）→ S3 对象存储（结构化）→ 应用（套壳上线）
- **对象存储命名规范**：量潮 `qtdata-provider`（平台数据）、量潮科技 `qtdata-private`（业务数据）
- **治理原则**：单向流动——流向更正式的资源后移除旧的，对正式资源做多道保护

## 数据质量：从真实项目中提炼质量口径

质量口径不是凭空设计，而是从真实项目里「用」出来的（没有反馈很难找，必须得用才知道）：

- 契约指标（如缺失率 ≤ 30%）与蓝图异常处理（重试/跳过/告警/自动适配）的对应关系
- 用业务活动反复验证资产是否真正帮助了业务

## 复盘与开源（本档案的核心用途）

每个真实项目结束后，回答并沉淀：

- **业务经验**：这个项目遇到了什么真实问题、怎么解决的
- **可复用结构**：哪些字段口径、处理流程、质量标准可以抽象成开源物
- **开源产物**：工作手册、基础教程、README、工具（CLI/Provider/Studio）

## 项目上下文

- **来源/客户**：第一个真实项目是量潮自己（自举）；后续目标是企业客户
- **交付形态**：数据需求文档、报价单、数据规格书、合同、进度汇报、交付清单、质量报告、复盘报告
- **工具链**：CLI（数据需求文档 DRD 流程）+ Provider（存储聚合）+ Studio（可视化/蓝图展示）
- **状态**：处于「真实项目落地 + 复盘开源」的持续迭代中
