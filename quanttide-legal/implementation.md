# 量潮算法备案数据集：数据实现

**层级**：数据实现（四层链路第四层，规格见 [specification.md](./specification.md)）  
**日期**：2026-11-05  
**状态**：待开发

实现层只做工程落地：技术栈、管道、命令行入口、校验脚本、版本管理与报告生成。所有概念、判定条件与口径来自数据意图，所有约束来自数据规格，本层不重新定义、不另立口径。

## 技术栈与选型理由

**选 Python**，理由按本项目实际的工程重心：

1. 本项目的负载是 IO 密集而非计算密集——生产步骤的瓶颈是调用被测模型服务（网络等待）与人工研判（人的时间），不是本地算力。Python 在调度、重试、并发编排上的开发速度优势完全覆盖这个场景。
2. 研判环节需要配套的小工具（盲评子集导出、结论导入、一致率计算），数量多而每个都小，Python 的迭代速度最适合。
3. 数据处理用 polars（与仓内搜索行为分析项目同一技术栈，先例可复用）；统计检验用 numpy 手算，不引统计库。
4. CUE 校验通过调用 cue CLI 完成，schema 文件与生成器、校验器三方共用同一份。

**Rust 的启用条件**（现在不用，写明触发条件避免将来随手重写）：变体生成成为 CPU 密集瓶颈（如关键词库量纲达到属地最高档、变体规则组合爆炸），或变体规则需要与词库处理合并为独立组件交付时，将变体生成器单独抽为 Rust 组件，通过命令行与本管道衔接。主管道不因性能预期提前换语言。

代码落位：当前阶段属最小验证，实现放实验室仓 `examples/quanttide-data-lab`；触发迁移的条件是与 qtcloud-data CLI 的 spec/pipeline 命令合并需求出现时，迁入平台仓作为子命令。

## 技术栈清单

- 语言：Python 3.12+
- 数据处理：polars，中间产物 Parquet
- 服务调度：httpx（异步，重试与超时按规格留档）
- 校验：cue CLI，schema 文件版本化
- 统计检验：numpy 手算（两比例 z 检验、Spearman、正态近似 p 值、Fisher z 置信区间）
- 报告：Markdown

## 数据管道

按规格层五步实现，每步一个命令行入口，产物与验收标准以规格为准：

| 命令 | 对应规格步骤 | 做什么 |
|:--|:--|:--|
| `spec` | 规格 | 校验规格书 CUE 与类别清单对照表，生成规格版本号 |
| `collect` | 采集 | 词库只读复制入库，登记来源、许可、日期 |
| `generate` | 生产 | 模板生成提示词 → 异步调度被测服务抓输出 → schema 校验与类别一致性拦截 → 写 questions/keywords（draft）与 runs |
| `judge` | 研判 | 导出盲评子集与研判界面数据、导入研判结论、计算一致率、状态机推进（draft → judged → verified） |
| `verify` | 交付前 | 覆盖差集复算、量纲核对、溯源完整率、全部指标计算 |
| `deliver` | 交付 | 打包交付包、附复算命令与结果、生成报告 |

## 质量校验脚本

与规格层质量校验一一对应，全部在 `verify` 命令内自动执行，不依赖人工记忆：

- schema 通过率检查：draft 入库即拦截，报告拦截记录数。
- runs 与输出文件数核对：每次运行的输出条数与运行登记一致。
- 覆盖差集复算：要求类别与 verified 产物类别比对，差集非空即失败。
- 溯源完整率：questions 与 keywords 的 run_id、source 全量回溯到 runs。
- 研判一致率：与规格版本中注册的阈值比对，低于阈值交付失败。
- 状态机检查：交付包内不存在 draft 或 judged 状态的题目。

## 版本管理

- 规格版本：spec_version 随法规与属地要求变化递增，是 runs 的登记字段。
- 运行版本：run_id 贯穿 questions、keywords、outputs，任何条目可回溯到一次运行。
- 代码与报告：git 提交哈希写入交付清单；报告与指标 JSON 一并落盘，两者数值一致。

## 执行验证

对 H1–H3 的回顾检验实现在 `verify` 命令中：每次交付自动把该批次的指标（三联完整率、变体多样性、覆盖完整率）与交付结果（通过、驳回及归因）写入交付历史库；样本积累后按意图层验证方法执行检验，统计量、p 值、效应量与置信区间写入 intent.md 的验证结论节。可行时按提示词模板版本做 A/B 比对；不可识别时只报相关。

## 报告生成

报告固定章节，与追溯矩阵的交付物一一对应：覆盖差集报告、研判质量报告、变体分布报告、溯源台账、驳回归因汇总。任何结论必须回指到具体指标与命题，不得由模型自由生成；报告与指标 JSON 同时落盘，数值一致。
