# 量潮算法备案数据集：数据意图

**层级**：数据意图（四层链路第二层，需求见 [requirement.md](./requirement.md)）  
**日期**：2026-11-05  
**状态**：命题未检验

本层把「为算法备案准备数据集」这一需求转成形式化验证：界定对象、给出操作定义、以类型约束产物形状、以结构保持的映射描述生成过程、建立指标与可证伪命题、指定验证方法。本层不写表结构、不写代码；可机器查的判定条件在「规格」层落成 CUE 校验。

## 意图陈述

> 对任意被测产品 P 与属地要求 R，从法规文本生产两类数据集——拦截关键词库 A 与评估测试题库 B——使其在类别覆盖、量纲、溯源、对抗覆盖上满足 R，并通过人工研判与独立验证。

句中每个名词在「形式化对象」与「操作定义」中落成可判定的东西；落不成的，回到需求层重述。

## 形式化对象

| 对象 | 记号 | 说明 |
|:--|:--|:--|
| 被测产品 | P | 四元参数：平台类型、备案类型、目标地区、模型能力与内容域 |
| 属地要求 | R | 该地区备案对类别、量纲、台账的具体要求集合 |
| 风险类别 | C | 国标附录 A 定义的类别空间，当前 31 类 |
| 规格书 | S | 法规文本翻译产出的结构化规格，含类别清单、量纲、字段约束 |
| 关键词条目 | k | 类别、关键词、变体、来源、日期、版本 |
| 题目 | q | 类别、提示词、模型原始输出、期望动作、安全研判、独立验证人、是否有效 |
| 数据集 | D | 产物，A 与 B 各一，由条目或题目按版本组织 |
| 验收结果 | v | 对 D 的校验输出，机器查与人工查分列 |

## 操作定义

- 三联记录 triple(q)：题目的提示词、原始输出、安全研判三字段均非空。三联合取成立是 q 构成合法题目的必要条件。
- 原始输出 raw(q)：由被测模型的真实服务对提示词运行产生，不接受人工编写或拼接的输出。
- 类别覆盖 cover(D, R)：D 的条目类别集合与 R 要求集合的差集。差集为空即覆盖完整。
- 有效题 valid(q)：经独立验证人判定为有效的题目。独立验证人必须与生成链路的执行者不同人。
- 变体派生 derive(k)：由既有条目按规则（同音、拼音、拆字等）生成的新条目，必须继承父条目的类别标签，不得自行改类。
- 对抗覆盖 adv(q)：题目属于多轮对话、提示注入、隐喻表达三类对抗场景之一。
- 溯源完整 prov(x)：条目或题目的来源、日期、版本三字段均非空，且版本可回溯到一次流水线运行。

## 类型层：产物的静态约束

产物形状以类型签名表达，落成 CUE schema 后由机器校验。题目 q 的类型：

```cue
q: {
	category:   =~"^C[0-9]{2}$"  // 类别编码，31 类之一
	prompt:     string & !=""    // 提示词，含变体来源标注
	raw_output: string & !=""    // 真实服务原始输出
	expected:   "拒答" | "正常回答" | "引导"
	judgment:   string & !=""   // 安全研判，人工产出
	verifier:   string & !=""   // 独立验证人，与生成者不同人
	valid:      bool
} & {
	verifier: !="生成者占位" // 校验规则：verifier 与生成者字段不同人
}
```

三联记录即 `prompt`、`raw_output`、`judgment` 三字段非空的合取；类型检查就是验收的一部分，不另设口径。

## 映射层：过程的动态描述

生成过程是三个映射的组合，每个映射有明确的保持性质：

```text
法规文本 R ──τ──▶ 规格书 S ──G_P──▶ 数据集 D(P) ──v──▶ 验收结果
```

- τ（法规 → 规格）：法规版本更新时只替换 S，G 与 v 不变。规格书是流水线唯一的法规接触点。
- G_P（规格 → 数据集）：按产品参数 P 实例化。P 变则 D 重跑，G 本身跨产品复用。
- v（数据集 → 验收）：机器查与人工查分列，机器查部分即类型层校验与覆盖检查。

不变式（交换图）：同一风险类别经不同生成路径——模板直接生成、变体派生、开源词库引入——到达的数据集条目，类别标签必须汇聚一致。等价地：变体派生继承类别、词库引入须先归类，任何路径不得产生无类别或错类别的条目。这一条是「类全」的形式化，也是「不错标」的生成时拦截点。

## 指标

| 指标 | 定义 | 分母 |
|:--|:--|:--|
| 类别覆盖完整率 | 覆盖差集为空的类别数 ÷ R 要求类别数 | R 要求类别数 |
| 三联完整率 | 三联合取成立的题目 ÷ 题目总数 | 题目总数 |
| 有效题率 | valid(q) 为真的题目 ÷ 已完成独立验证的题目 | 已验证题目数 |
| 研判一致率 | 双人独立研判结论一致的题目 ÷ 双人研判题目数 | 双人研判题目数 |
| 变体多样性 | 每类别下变体来源种类数与变体条目数的分布 | 按类别统计 |
| 对抗覆盖占比 | 三类对抗场景题目数 ÷ 题目总数 | 题目总数 |
| 溯源完整率 | prov(x) 成立的条目与题目 ÷ 全部条目与题目 | 全部条目与题目 |

聚合维度：全局、按类别、按产品 P 三层，便于下钻到具体类别与具体产品。

## 命题与假设

| 假设 | 内容 | 可证伪条件 |
|:--|:--|:--|
| H1 | 三联完整率高的交付，有效题率更高 | 三联完整率与有效题率不相关或负相关 |
| H2 | 变体多样性不足的对抗类目更易被审核驳回 | 多样性与驳回不相关或正相关 |
| H3 | 类别覆盖完整率与备案一次通过率正相关 | 覆盖完整率与通过率不相关或负相关 |

因果图：

```text
spec_version(规格版本) → variant_diversity → review_rejection
prompt_template_version → variant_diversity
human_judgment_quality → valid_rate → review_pass
coverage_gap → review_rejection
```

混杂变量：备案类型、地区、产品内容域。H1–H3 先按相关命题处理；因果方向须经识别策略确认（见「验证方法」），未识别的不得冒称因果。

## 约束与不变量

- 覆盖不变式：categories(D) ⊇ required(R)，差集可一键复算。
- 三联不变式：入集题目三联合取成立，schema 层拦截。
- 溯源不变式：全部条目与题目溯源字段非空且版本可回溯。
- 量纲不变式：D 的量纲满足 R 的要求，量纲参数按属地可配置、不写死。
- 交换图可交换：类别标签在任何生成路径下一致。
- 阈值先注册后跑、跑完不改：覆盖判据与相似度阈值的取值在生成前写进实现并留档。
- 验证人独立：verifier 与生成链路执行者不同人，schema 层校验。

## 验证方法

- 机器查：schema 校验（三联、溯源、量纲、验证人独立）、覆盖差集复算——在规格与实现层落地，本层只判定条件。
- 人工查：安全研判与独立验证；研判一致率以双人独立研判比对度量。
- 统计检验：H1–H3 以每次备案交付为试验点做回顾检验；比例用两比例 z 检验，相关用 Spearman 或卡方，报告效应量与置信区间。
- 因果识别：提示词模板版本可作为自然实验做 A/B 比对；不可识别时只报相关。
- 偏差控制：按备案类型、地区、内容域分层，避免辛普森悖论。
